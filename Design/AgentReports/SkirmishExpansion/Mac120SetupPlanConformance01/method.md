# Audit method and limits

This extends the earlier MacConfigOnlyGapReview01 source-only review, pinned in source-pins.json, at the assigned exact committed base. No shared/Menu source is edited or used as current identity. Only selected plan CSVs, catalog/definition/logical assets, their dependency metadata, source functions and two bounded historical evidence reports are read/pinned. No terrain/scene/library/SDK hashing or native/compiler operation occurs.

Each table row retains its complete planned budget, source row line, materialized definition and typed-reference fields, linked source-file hashes, fit-reference JSON pointer, compiler-evidence scope and bounded next action. Plan/catalog/manifest/BattleCatalog identities are compared. Canonical infantry/ground/air/combat totals and supply weights (infantry1,car/APC4,tank/AA6,transportheli8) are recomputed for both sides, alongside squad multiples and cap limits. Fixed stock scaling is Standard1,War3/2,LargeWar2 with integer division; all eight size caps, readiness and applicable typed deadline fields are checked against their committed assets/source. BA deadline defaults apply only to BA; generic non-BA authoring copies each objective-specific planned deadline, including FC Standard1200. Selected materialized definitions additionally compare typed army/start/objective and budget scalars. This is source projection, never TryCompile execution.

The setup compiler takes the individual role counts, queues, support and several counts directly from the matrix, so their presence in a row is not independent compiler proof. Extra roles absent from the matrix, native actual roster membership, loaded vehicle fuel totals, original designated actor identities, placement, source-fit, runtime dispatch and end-to-end acceptance are not established here. The named loaded_vehicle_fuel requirement is retained as an unresolved normal/native accounting requirement.

Persistent scenario definition inventory is the exact Scenarios/*/SkirmishScenario_*.asset scope, cross-checked against the packaged expansion refs; packaged S002 duplicate is separately pinned. Compatibility factory CreateInMemory has four explicit coded definitions; it does not materialize120. Legacy counterpart bindings are counted separately from missing new authoring. The full120 fit-input report is historical, declares unqualified scope and stores proposals; embedded row equality is checked but does not refresh its provenance. Existing compiler receipt advertises12codedbaseline configurations and various fixtures; no source-consumption join to this exact base is established, so no current row is credited.

Source files and report payloads are hashed only within this bounded audit input set. All failures, gate states, Campaign map reuse, coded grants and other owners remain preserved. Windows source6a/build26f is a different dirty native identity. This review grants no implementation, launch, compile, restoration, cleanup or acceptance authority.

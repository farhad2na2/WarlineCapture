Branch `missions/win-w27-aria-stops` (from integration `2441e8270`). The Windows dev lead did this task, with a read-only code and log read by a subagent; the key citations were spot-checked. No Unity run, no code change.

Cases: six `ariaStopped:Blocked` aborts in non-counted menu runs.
- S061 and S068: `win-dev-unity\w23b-mp-bt` and `w23b-mp-ce`.
- S074: `w29-s074-e`.
- S075, S076 and S078: `w29-s075-s078`.

Log line numbers below refer to each run's `menu\unity.log`.

## How the stop codes work
- **101: planner-set Blocked** (`AriaSkirmishPlanSystem.cs:58-59`). On the expanded Base Assault path it comes from one of two places:
  - a foreign popup (`:824`, always intent Inspect first);
  - **the 180 s ground-progress watchdog** (`:892` → `AriaGroundProgressPolicy.Observe`, `AriaGroundColumnPolicy.cs:309-316`). It fires when 180 s pass with no change in enemy HQ HP, player HQ HP, infantry count, an air milestone, supply progress or assault advance.
  - On the FC/BT/CE path, 101 also comes from a missing objective frame for more than 20 s (`AriaSkirmishPlanSystem.ObjectiveSkill.cs:52-53`, `AriaObjectiveSkillPolicy.cs:41,99`).
- **115: the input layer stops** after 3 presses of the same target without a change (`AriaPlayDecisionSystem.cs:109`).
- **111** (`:35-37`) fired in none of these cases.

## Per case
1. **S061, Mountain Pass BT (115).**
   - The first group-19 ground tap (t≈134 s) was accepted by the game: an AcceptedMove banner at ≈136 s, log 6438. ARIA's receipt never matched it, so the 8 s receipt deadline (`AriaSkirmishPlanSystem.Objective.cs:47-48`) made it `order_retry` 1 at 155.5 s. Retry 2 at 207.5 s: unproven.
   - After the retry, Move is re-published every frame (`Objective.cs:88`) and pressed 3 times while `moveMode=False`.
   - The planner's own bound (`RejectedAttempts>=3`, `:58`) is checked before `Publish` raises the count. The input layer's `Attempts>=3` fires first in the same frame.
   - Evidence: log 6514, 6563, 6606, 7249, 7265.
   - **ARIA code: two bounds of 3 race, plus a receipt mismatch.** Why Move did not arm is unproven.
2. **S068, Mountain Pass CE (101, frame).**
   - `RepairVehicle` choices at 161.9, 189.2 and 216.5 s each end 25 s later. `SkirmishConvoyServiceJourney.cs:114/116` calls Retry, and on the third failure (`:20`) moves to Handback.

   - FieldRepair never offered `Action=Repair`. Which gate fails is unproven; `!Eligible` against the 12 m pad radius is a candidate (`FieldRepair.cs:15-20/63-64`).
   - Evidence: log 77454 … 80396.
   - **ARIA code: Handback blanks the objective frame.** Possibly also service-pad data.
3. **S074, IB BA ground (101, 180 s watchdog).**
   - The popup source is ruled out: the intent was Recruit.
   - The player base stays at 800/800 HP, and only 14 commands were issued in 337 s.

4. **S075, IB BA air field (115 on AdvanceGround).**
   - Player groups 1, 2 and 16 attack-moved to cell (844,490), about 23 m from the enemy base (accepted, frames 4543, 4606, 5472).
   - The Advance branch (`AriaSkirmishPlanSystem.cs:968-976`) re-offers the same ground every frame while AttackMode and SelectionVisible hold. It has no latch or bound, unlike `AriaFindBasePolicy`.

- **Contrast, S077:** a normal Defeat (MainBaseDestroyed, 216.8 s). The player base took damage, which counts as progress, so the watchdog never fired (log 309148).

## Cause list (deduplicated)
1. **The input layer's bound races the planner's own bounded retry (S061, S075).**
   - The planner re-publishes the same control (Move, or AdvanceGround) every frame. `AriaPlayDecisionSystem.cs:109` stops ARIA before the planner absorbs the failure.
   - Code only. Fix: latch or bound the re-offer (as `AriaFindBasePolicy` does), keep the planner's bound below the input layer's, and check the receipt join (`SkirmishMatchView.PublicObjectiveHud.cs:241-246`).
2. **On Industrial Basin, the assault never reaches or damages the enemy base, so the 180 s ground-progress watchdog fires (S074, S076, S078; S075 shares the geometry).**
   - No base or advance target is offered (S074), and an untargetable intruder holds ARIA in DefendBase (S076, S078).
   - Base Assault has no progress signal besides HP, infantry, milestones and closest approach.
   - Data side: another Campaign source, or force and pad tuning, under the reuse policy.
   - Code side: count accepted orders or arrival as progress, make the IB approach legality-aware, and let home defense engage what it alerts on.
3. **A convoy-service Handback blanks the objective frame, and the 20 s frame Block fires (S068).**
   - Code, plus a FieldRepair eligibility gate that is still undiagnosed.

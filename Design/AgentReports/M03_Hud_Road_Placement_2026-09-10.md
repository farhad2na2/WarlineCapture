# M3 HUD, road placement, and mobile controls

The alert was controlled by multiple presenters. Building placement repeatedly hid it while the warning presenter repeatedly showed it. The warning now has one visibility controller, and placement leaves it visible. Popup and command targeting suppression respect warning expiry instead of restoring a stale visibility snapshot.

The wide M3 controls panel below the warning is removed. Field guide and optional lesson actions sit inside ARIA. Tapping the alert opens its details; camera return is a contextual header action. Radar charges and cooldown use the existing radar command. M3 and M4 mission actions use 72-unit-high controls with spacing, and the M3 minimap reserves room below them. The selected unit's whole portrait remains clickable for Commands, with a larger visible cue that also fits the compact passenger layout. The passenger control is 72 units high, and its icon and label retain their enlarged layout when the drawer closes. Field-guide navigation controls share the same minimum height.

Placement previously checked generated roads and blockers but missed the authored mission road geometry. A map-scoped cache projects road surfaces and mesh triangles into placement cells. It includes partial overlaps and rotated road edges, survives the end of startup's bulk placement transaction, and refreshes when the map/mesh revision changes. Preview, confirmation, and wall queries consume that cache. No reward, cost, or progression rules change.

Validation used the checked macOS wrapper and an isolated Editor project. No Android validation was performed, as requested.

## Causes and evidence limits

- Initial 1102 and 2102 likely hit O001's 180-second startup limit at `Assets/Game/Scripts/Composition/OperationsMissionPresentationSystem.cs:354`. The first two shared-city SubScene imports took 247.89 s and 257.49 s at `02-aria-en-1102.log:1162` and `03-aria-en-2102.log:1004`. Each was retried once after the shared scene was cached.
- Both retries, 3102, 4102, FA, Recruit, Veteran, checkpoint resume and lifecycle completed `EnterMatchHud` before reporting the deployment refund. For example, see `04-aria-en-3102.log:1070`, `:1192` and `:1226`. O001's `TrySpawn` preflight may be rejecting the shared navigation grid, prefab registry or placements at `Assets/Game/Scripts/Composition/OperationsReconSpawnCompositionSystemHelper.cs:31`. `Assets/Game/Scripts/Composition/OperationsMissionPresentationSystem.cs:112` stores the error, while `:352` and `:365` collapse several startup failure paths into the same refund notice. The logs leave the precise condition unverified.
- The manual Victory observer reached the main menu at `09-manual-victory.log:774`. Computer control resolved both the Unity app name and path to the main checkout's Editor window, which shares the lab's bundle and executable. The lab observer received no test input and timed out at stage 0. The observer waits for normal mouse and keyboard input at `Assets/Game/Scripts/Editor/OperationsReconLaunchSmokeValidation.cs:816`, and the timeout is at `:242`. `[OperationsReconManualAcceptance] result=` requires a settlement and return through `:852`, which this run did not reach.
- The manual Partial observer reached the menu at `10-manual-partial.log:775` and received no test input. The native stack points to Unity's `ProfilerFrameDataDeserializer` at `10-manual-partial.log:1367`, following the profiler buffer warnings. The crash interrupted the observer at `Assets/Game/Scripts/Editor/OperationsReconLaunchSmokeValidation.cs:816` before any mission outcome. Both manual runs lack a `[OperationsReconManualAcceptance] result=` marker. Real player and device acceptance remain pending.
- Each Editor log's first error diagnostic at line 21 is `[Licensing::Module] Error: Access token is unavailable; failed to update`. The logs subsequently show entitlement resolution and method execution. The compile log also reports Burst `BC1016` at `01-compile.log:19517` for `Assets/Game/Scripts/Simulation/AriaExpandedPreparationPolicy.cs:175`. The same diagnostic appears at startup in the O001 logs. The 0 `error CS` count applies to C# compilation, and the relationship of the Burst diagnostic to the O001 deployment failure is unverified.
- Unity rewrote two text-alignment values in the lab's `SCN08_MatchHudContent.prefab` on exit from the Persian run at `06-aria-fa-9102.log:1240`. Recruit and Veteran inherited those generated values. The two-line diff is preserved as `06-persian-generated-prefab.patch`. The prefab was restored to HEAD after Veteran and before the warm retries, checkpoint, lifecycle and manual runs. Those automated runs still reported the refund. No harness or gameplay changes were made.

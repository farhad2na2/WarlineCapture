# Shared combat, damage sequencing and movement replay

The production `UnitAttackSystem.PlanStandardAttacksJob` delegates to
`Game.Runtime.Combat.StandardAttackPlanner`. The damage commit loop now calls `DirectDamageSequencer`, and native infantry
path following calls `GridPathMovementKernel`. These same source files compile on
.NET 8 without Unity, package downloads, graphics or physics. This allows quick
checks of attack configurations and candidate snapshots before native tests.

## Commands

Use fresh, short output paths. Replace `/private/tmp/...` with `D:/W/...` on Windows
and use `python` instead of `python3` where appropriate.

```sh
rtk proxy python3 -B Tools/CI/skirmish_combat_replay.py build --project . --output /private/tmp/combat-build-01
rtk proxy python3 -B Tools/CI/skirmish_combat_replay_test.py --build /private/tmp/combat-build-01 --output /private/tmp/combat-tests-01
rtk proxy python3 -B Tools/CI/skirmish_sequence_replay_test.py --build /private/tmp/combat-build-01 --output /private/tmp/sequence-tests-01
rtk proxy python3 -B Tools/CI/skirmish_combat_replay.py run --build /private/tmp/combat-build-01 --input /private/tmp/combat-tests-01/examples.json --output /private/tmp/combat-run-01
```

The attack tests write `examples.json` with 30 complete candidate cases. The
sequence tests write a separate `examples.json` with 19 damage, movement and
occupancy fixtures.
Copy that file outside Assets, change the inputs and expected results, then run
many times against one build. Any change to the kernel, runtime adapter, harness
or driver requires rebuilding; their exact hashes and the binary hashes are
checked before and after every run. Outputs preserve the captured input, process
logs and each actual plan. No run silently overwrites previous evidence.

## Input

Root: `{"schema_version":1,"cases":[...]}`. Each candidate has:

- `id`: unique nonempty label (not evidence of mission identity).
- `input`: every field of `StandardAttackInput`, including every nested `State`
  field. Positions are XZ world coordinates, ranges/radii use world units, and
  clocks use seconds. All values must be finite; byte flags must be 0 or 1.
- `delta_time`: finite, nonnegative seconds for this planner invocation.
- `cell_size`: finite, positive world units.
- `expect`: nonempty subset of output fields to compare exactly, including
  `Kind` (`None`, `ClearTarget`, `Windup`, `Shot`), `BaseState`, `State`, `Damage`
  and `ShowTracer`. Float expectations use the emitted JSON float values with no tolerance;
  equivalent number spellings such as `1` and `1.0` compare equally.

Rows without `kind` remain independent candidate snapshots. They do not advance
state between rows. For ordered damage and retained movement, use the sequence
row kinds below. No mode invents animation clocks, targeting or path admission. Empty/unknown/missing fields, duplicate JSON keys and IDs,
invalid types, false expectations and stale builds fail. Errors are aggregated
across independent cases. Limits: 16 MiB input, 10,000 cases and a 120-second
process timeout. Exit zero requires all expectations to pass.

## Production behavior preserved

The shared planner retains base cooldown/trace ticking, invalid-target clearing,
horizontal range with combat radii and a quarter-cell allowance, aircraft-window
checks, windup, shot cooldown, animation duration, tracer cadence and phase.
Windup uses the original cooldown as well as the post-tick eligibility check.
`BaseState` remains separate because a planned shot can be discarded by the host
when an earlier attack has exhausted the target's predicted health.

`DirectDamageSequencer` preserves cover rounding and minimum positive damage,
unchecked integer arithmetic, ordered predicted-health gates, delayed health
application, first observation source, last attacker and tracer aggregation.
Windup still commits before the predicted-health gate. A shot skipped due to
overkill keeps its base tick and does not consume a shot counter or cooldown.
Zero-damage shots still consume shot state. Actors that were alive in the snapshot
can kill each other in the same update. The original missile lane remains before
the standard candidate lane; their native ordering is unchanged.

Production targeting and eligibility filters, no-engagement recovery, animation
ticks, native world/occupancy queries, vehicle/air steering, audiovisual effects
and objective evaluation remain in their current systems. A zero delta alone is
not a pause gate inside these kernels; the host owns pause/terminal dispatch.

## Sequence input kinds

Each sequence row has exactly `id`, `kind`, `input`, `expect`. All nested fields
are required; editable examples are generated by the sequence test command.
The public input contracts are in `SkirmishOfflineSim/SequenceProgram.cs`.

- `damage_sequence`: a frozen `Targets` array and ordered `Candidates`, with
  `DeltaTime` and `CellSize`. Each candidate carries the full planner input, source
  entity index/version/cell/position and attacker-exists fact. Snapshot target
  health/existence and source position must agree. Repeated attacker identities
  are rejected. Health commits after the whole ordered batch; the result includes
  shot decisions, actual committed states, predicted/final HP and attribution.
  Cover eligibility is an externally resolved fact, after air/building/grid rules.
  This mode models standard candidate commits; missile eligibility/planning is
  not implemented offline.
- `infantry_trace`: an `InitialState`, explicit path cell/world coordinates,
  effective speed, arrival radius, cell size, group flag and ordered `Frames`.
  State persists across frames; each frame uses the native eight-waypoint cap.
  Every frame must declare known, admitted path-follow entry facts. Group arrival
  requires the externally resolved settled grid cell. This replays the inner
  infantry path-follow loop **after native admission/pre-loop checks**. It does
  not run grid conversion, footprint checks, pathfinding, vehicle steering or
  the outer native arrival branches. Effective speed and initial cell must
  already include the native host's adjustments.
- `movement_gate`: shared range/blocker/occupied-stall decisions for infantry.
  `CellBlocked` and `OccupantBlocks` must already account for the current
  footprint, self/group/boarding occupants and friendly-pass policies. Unknown
  facts fail. It reports wait/repath timing; it does not prove the route legal.

Path-admission assertions are supplied evidence, not a route-validation result:
`RouteLegalityProven` stays false. Cases remain independent of each other, and a
case ID is a label rather than proof of a catalog mission's readiness.

## Validation layers and next priorities

The offline suite checks 30 boundaries, 10,000-case repeated deterministic output,
malformed input, stale source/binary rejection and safe output isolation. Native
`StandardAttackPlannerTests` compares the new kernel against the original method
with actual Unity math, exercises Burst and checks the production ECS adapter.
Run its focused entry point through the checked repository wrapper and require
its explicit pass marker; offline passes are not substitutes for native checks.

On macOS, keep Hub signed in, confirm this project has no active Editor owner,
then use the checked GUI-licensing wrapper (or its supported `--reuse` mode for
an admitted idle Editor). Protect unrelated Editors.

```sh
rtk proxy Tools/CI/invoke_unity_macos.sh --timeout 900 --log /private/tmp/combat-native-01.log -- -quit -executeMethod Game.Tests.Editor.GridPathMovementKernelTests.RunCombinedValidation
```

Require wrapper exit zero **and** `[SharedCombatMovementParity] result=Passed`
in the complete log, with no compile failure or failed-test marker. A zero Unity
exit on compilation failure is a failed validation. On Windows use
`InvokeUnityExecuteMethodValidation.ps1` with the same method and required marker,
the resolved project Editor version, explicit timeout and a fresh full log.
The oracle records both raw and canonical LF hashes for explicit CRLF portability;
only the test fixture permits this normalization. Runtime/build pins remain byte-exact.

These are shared simulation steps, not a complete mission simulator. Reports keep
`full_battle_simulated=false`, `mission_qualified=false` and `native_runs=0`.
Next extract native pathfinding/occupancy, vehicle/air movement, animation timing,
targeting and AI/economy kernels; then produce objective facts from those systems and
compare native/offline traces. Mission UI, ARIA, result/return and device acceptance
remain separate gates. Keep map reuse policy, catalog bindings and gameplay budgets.

## Initial verification, 2026-10-23

Seven standalone test groups passed with no skips, including 30 boundary cases
and two identical 10,000-candidate batches. The Mac native focused suite passed
five parity tests plus six existing combat tests, with an explicit compiled-Burst
sentinel and unchanged source/settings hashes. Earlier compilation failures were
retained and repaired before the successful run. The successful Unity shutdown
reported four persistent allocations without attribution; that lifecycle warning
remains open and is not represented as a clean leak check or mission acceptance.

A subsequent run of the same published candidate with per-process
`UNITY_JOBS_NATIVE_LEAK_DETECTION_MODE=2` again passed all eleven native checks
with unchanged source/settings. Its four allocation stacks identify Unity
Entities package storage: two static component-safety buffers, the shared
per-chunk array and global entity-store storage. None of the reported stacks
points to the attack planner, its scratch maps or the new parity arrays. Package
ownership is established; shutdown cleanup timing versus retained storage is
still unresolved. No game/package cleanup bypass or leak suppression was added.

source/adapter files. The seven existing attack/integrity test groups and three
new sequencing groups pass, including 19 new boundary fixtures and 16 negative

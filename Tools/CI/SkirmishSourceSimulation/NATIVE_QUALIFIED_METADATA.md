# Native qualified immutable metadata

This successor uses the existing building, unit and configured-provider readers. It adds a qualified schema 2 path for exact native metadata facts, with a pinned capture and actual compiled context. It does not add a public mission execution profile.

The S026 native qualification is SHA-256 `06ff2cf07f069988a04f9e1740cbc9d29461207014b566fe3f2845c205e7be17`. Its 12 size/difficulty contexts at seed 104755 select nine buildings and sixteen units. These are different from S002: production slots, recipes, delivery timing and configured unit order differ. The old S002 artifacts must remain unchanged and are rejected as S026 projections.

`Recipes/project_native_qualified_metadata.py` projects each exact native context into three schema 2 artifacts. Building fields, unit metadata, immutable prefab identities and transport graphs are copied without substitution. The configured supplement copies actual requestability/display values and raw provider indices (a native absent index is represented as null, matching the reader contract). Headers identify the native artifact, catalog, size, difficulty, seed, setup hash and native metadata digest. They describe metadata-only scope; no session entities, opening positions, storage bank or runtime state is projected. Native source/dependency identities are retained. No Campaign geometry is authored.

The compatibility bridge checks the exact capture, actual current compiled setup, grants/roles, target binding, native domain, all consumed factory sources and script metas, six owner assembly definitions and metas, conservative native asset closure and package manifests. It rejects old S002 schema/provenance, mismatched targets and changed facts. The readers admit the native context's count only after that qualification; S002 schema 1 keeps its original strict eight-building/twelve-unit behavior.

The production adapter compares current role-derived recipes and the original source delivery-timing calculation with the qualified native context before production inputs are published. Static catalog getter decoding uses the already-admitted unit metadata/count; no native rendered-input or player acceptance is claimed.

Run the projection tool with explicit `--native`, `--bridge` and a fresh `--output` directory. The isolated no-World qualification controls recorded in the validation evidence are not installed public CLI entry points. Their frozen authoring graph/layout references are qualification inputs, not runtime mission aliases. Those controls compile all twelve actual configurations, read nine buildings/sixteen units, check configured getters and original recipe/timing facts, and reject altered origins, contexts, fields, provider indices, old references and wrong target bindings.

Existing full mission/native normal-input/device gates remain separate. A qualified metadata artifact does not authorize a public S026 run or establish mission readiness.

## Declared compiler inputs on a captured Campaign source

`Recipes/project_native_qualified_metadata.py` also exposes
`project_declared(...)`. The existing `project(...)` function and its native
projection CLI are unchanged. The optional function accepts one actual selected
compiler variant and writes the existing declared initialization/data schemas;
it does not initialize a World or grant runtime/native/player readiness.

This is **runtime admission and pinned-artifact projection only**, not a
self-contained mission configuration or genuine-context compiler. The public
recipe does not currently generate
`actual_original_compiler.actual_derived_factory_context`; a qualified external
original-compiler/context exporter must supply that pinned result. The previously
qualified exporter used private glue and is not silently included in this payload.
A public data-only original-compiler-to-context export seam and mission-owned
S074/S098 logical configuration inputs are separate pending deliveries.

Pass an actual original-compiler result with its genuine derived factory context,
not a rewritten target header. If the source repository changes, regenerate that
context through the original producer against the actual repository. The native
factory artifact, physical readback, full source graph/layout and numeric function
reference set remain independently pinned external inputs. Captures are not
bundled by this recipe, and numeric-function evidence keeps its original capture
provenance when reused by another source with the same exact input keys.

The request is a JSON object matching the function's keyword parameters:

- `compiler_result`, `physical`, `graph`, `layout`, `function_set`,
  `camera_function_profile`, `initialization_template`, `bundle_template`:
  exact `{"path": absolute_path, "sha256": digest}` descriptors.
- `current_assets`: `definition`, `grid`, `surface` descriptors, each with the
  current repository-relative `source_path` in addition to `path` and `sha256`.
- `bridge_path`: the current `Adapters/SourceMetadataCompatibility.cs` source,
  whose existing `FactorySources` roster owns the configured metadata pin subset.
- `output`: a fresh directory. Keep the shared templates' immutable native/input
  descriptors; the actual compiler supplies target, binding, layout and view.

Run an external request without modifying the legacy CLI:

```sh
python3 -B - Tools/CI/SkirmishSourceSimulation/Recipes/project_native_qualified_metadata.py /absolute/request.json <<'PYCODE'
import importlib.util, json, sys
spec = importlib.util.spec_from_file_location('metadata_projection', sys.argv[1])
module = importlib.util.module_from_spec(spec)
spec.loader.exec_module(module)
module.project_declared(**json.load(open(sys.argv[2])))
PYCODE
```

The original schemas retain separate binding `ContentVersion` and definition
`DefinitionVersion` domains. The native-origin projection includes its original
six identity fields plus artifact kind and digest. Negative native provider
indices project to JSON null. Configured metadata uses only the original factory
owner roster; the complete native closure remains in its context/definition/unit
provenance. Navigation uses the actual row list, and drop completeness uses the
actual `dropClearanceBounds.bounds` array. Source/frame/array/function semantics
remain the original runtime validators' responsibility.

Compiled structure anchors are preferred points. A successful headless joint
search may use legal fallback rectangles; do not rewrite those as compiled
anchors or infer typed-pad, route, active-water, native camera, or player acceptance.
Run the ordinary collector and normal CLI guards before normal World/ARIA checks.

Run the focused Python pin/header controls through the existing exact-byte
bootstrap (the schema-2 reference set is supplied externally):

```sh
python3 -B Tools/CI/tests/run_declared_admission_protocols.py --ci-root Tools/CI --mode header
python3 -B Tools/CI/tests/run_declared_admission_protocols.py --ci-root Tools/CI --mode rotation --reference-set /absolute/qualified-reference-set.json
```

These are protocol/data checks only. Native data capture, original compiler
roundtrip, headless placement, normal bounded runs, natural full outcomes and
native/player acceptance remain separate evidence.

## Original compiler and context export

The existing `author` command accepts a `SkirmishDeclaredCompilerExportDraft`. It invokes the original setup compiler and the existing metadata compatibility owner. It exports the original portable binding fields and a genuine context for the actual `--repo` root. It does not create a World or establish physical fit, native mission, or player readiness.

The request pins a source configuration graph, the original setup matrix, a logical layout, original declared binding fields, and a `QualifiedNativeMetadataOrigin` descriptor. `profiles`, `campaign_source_path`, `catalog_id`, `seed`, `size`, and `difficulty` remain explicit original inputs. Source graph files must be under the actual source/data roots or the source/data roots from the pin-verified native-origin descriptor. Every graph file digest is still checked. Historical graph snapshots are graph inputs; they are not relabelled as current native capture files.

S074 and S098 owned logical inputs are under `Design/Skirmish/DeclaredInputs/`. External source graphs, native factory metadata, native origin inputs and physical/function captures remain separately supplied and pinned. The graph and origin files are not generated by this command. The exporter uses the existing raw declared-field encoder/decoder and original compiler; it does not infer missing values or replace the original framing/placement owners.

```sh
python3 Tools/CI/run_skirmish_source_simulation.py author \
  --repo "$SOURCE_REPO" --package-root "$SOURCE_PACKAGE" \
  --mission "$CATALOG_ID" --seed "$SEED" \
  --authoring-input "$PINNED_DRAFT" \
  --build-receipt "$TYPED_BUILD_RECEIPT" \
  --data-repo "$ASSET_REPO" --timeout 120 --output "$FRESH_OUTPUT"
```

A supplied typed build receipt must belong to the actual source repository and its original source/reference pins remain authoritative. The existing separate package root selects owned tool code; it does not rebase the build receipt or the generated context. Omitting the receipt builds the existing typed data-tool closure. The compilation profile selects a tool closure only and does not substitute a mission identity.

`CompilerContextExported` requires an actual original compiler pass and a generated context. Compiler rejection and runtime failure remain visible in the result, process log and invocation receipt. Runtime manifests bracket the data operation. No compilation or export result alone admits a normal mission or marks it ready.

The exporter retains the strict version-1 captured factory composition checks. Inputs with a different ordered factory domain are rejected.

### Reusable checks

The root check is pure Python and requires no captures or compiled image:

```sh
python3 -B Tools/CI/tests/run_declared_compiler_origin_checks.py --output "$FRESH_ROOT_CHECKS"
```

Optional `--request` arguments verify supplied graph pins too; supply `--source-repo` and `--data-repo` for those cases. The native-origin descriptor is pin-verified here to establish allowed graph roots. The original C# owner still validates native artifact identity, factory sections and complete consumed-file coverage.

The comparison check requires an existing typed build receipt and explicitly pinned external case descriptors:

```sh
python3 -B Tools/CI/tests/run_declared_compiler_export_comparison.py \
  --source-repo "$SOURCE_REPO" --package-root "$SOURCE_PACKAGE" \
  --data-repo "$ASSET_REPO" --build-receipt "$TYPED_BUILD_RECEIPT" \
  --cases "$PINNED_CASES" --output "$FRESH_COMPARISON"
```

The case document has `schema_version: 1` and a `cases` array. Each row supplies `catalog_id`, `seed`, `request` (`path`, `sha256`), `expected_actual_setup`, and `original_qualified_comparison_result` (`path`, `sha256`). Requests use the existing declared compiler draft schema. The check invokes the public `author` command, compares original setup/structures/portable fields and all six native factory sections, verifies loaded runtime identity and consumed pins, and stops at the first failure. It does not create a World or supply missing external captures.

The owned S074/S098 JSON files contain logical source inputs in existing layout and binding formats. Their source-only and readiness flags remain unchanged; successful export does not promote those inputs to native mission readiness.

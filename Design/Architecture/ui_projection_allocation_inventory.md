Status: preparatory inventory for `AM-026`; not accepted and not counted complete.

This inventory may be maintained while `AM-020` through `AM-025` close, but Phase 3 production changes remain gated by the accepted Phase 2 cache and lifecycle contract. It covers the currently implemented Canvas runtime surfaces and records the owner that initiates reads, the source/version contract, managed conversion or rebuild behavior, existing allocation coverage, and the task that owns remediation.

## Acceptance Contract

Every surface must satisfy all of these rules before `AM-026` can close:

1. Read source identity and semantic version before converting `FixedString` values or constructing managed models.
2. Cache identity includes the bound `World`, boundary entity, relevant source versions, item counts, settings/localization version, and explicit invalidation reason.
3. Rebuild only when visible semantic data changes. Time-based animation may update independently without rebuilding unchanged data.
4. Unchanged open-state coverage uses at least `180` warmup and `300` measured frames and attributes exactly zero recurring production-owned managed bytes to the surface.
5. Opening, closing, World replacement, scene unload, localization refresh, settings changes, resolution changes, and version rollover are measured separately from unchanged steady state.
6. A view-local `Update()` loop is not accepted by default. `AM-034` must remove it or record why a centralized shell refresh cannot own it.
7. No projection path may discover `World.DefaultGameObjectInjectionWorld` or create temporary native containers during a recurring managed UI read.

## Initial Priority Order

1. `UI-015` Resource Exchange: preserve the ECS fingerprint/version and move the managed cache check before every conversion. Draft package `AM-WP-001` defines the bounded implementation, but it cannot execute until Phase 2 acceptance.
2. `UI-013` Build Drawer: draft `AM-WP-002` preserves live Canvas behavior, introduces one World-bound managed projection cache after `AM-027`/`AM-028`, and retires duplicate/dormant projection ownership in bounded slices.
3. `UI-008` Selection and `UI-010` Passenger Drawer: draft `AM-WP-003` preserves the existing semantic apply caches, adds source-first structural/status/passenger versions, moves unchanged checks before timed scans/publication, and retires default-World/temporary-array debt from the dormant adapters.
4. `UI-014` Placement: draft `AM-WP-004` preserves direct command behavior, introduces one visible-semantic projection version, removes unchanged string polling, and retires the unconfigured duplicate ECS/gateway path. `UI-007` ARIA needs lifecycle/invalidation completion, not a cache redesign.
5. Remaining Menu/HUD surfaces: standardize invalidation and add the full open-surface matrix.

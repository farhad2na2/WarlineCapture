# Airport feasibility on City Crossroads, Mountain Pass and Industrial Basin (2026-11-19)

Read-only study. No Unity run, no asset or code change; this file is the only output. Branch `missions/integration` at `ec3a948d4`.

## How it was measured

These are offline estimates. They are not native placement results.

- **Scenery and roads.** The study used the committed layout dumps (`Design/AgentReports/SkirmishExpansion/LayoutDumps/{S002,S026,S050}/dump.json`, and S074 from `origin/missions/win-w29-ib-ba`). Each dump has a 4 m bitmap with these flags: road, water, authored scenery, invalid, not level, and sidewalk. A 4 m block counts as blocked if any flag is set, which is conservative.
- **Surface.** The shared-world surface `Assets/Game/Data/MapSurfaces/Match_Map_MapSurfaceData.asset` was decoded the same way as `MapSurfaceDataAsset.TryReadSingleLayerGridPayload` (`Assets/Game/Scripts/Configs/MapSurfaceDataAsset.cs:388-450`). The Citywide Alert and Armor Break packages were decoded from their own `Grid.asset` and `Surface.asset`.
- **Placement rules applied.** These are the native Skirmish placement rules:
  - every footprint cell needs the `BuildingPlacement` surface bit (`Assets/Game/Scripts/Systems/BuildingPlacementAdapterCompositionSystemHelper.cs:136-178`);
  - while Playing, the footprint must be level: height spread ≤ 0.5 m, elevation ≤ 0.75 m, slope ≤ 8° (same file `:15-17` and `:181-225`);
  - the footprint must not overlap the current draft pads.
- **Cross-check against the shared world.** The CC and IB dump bitmaps match the S002 whole-world bitmap 100 % where they overlap. Citywide Alert matches only 66 %, because it is its own derivative package.
- **Ground reachability.** All candidate sites below lie in the same vehicle-passable component as the bases. This was checked with a 4 m flood fill, so it is coarse.
- **What still needs proof.** Every site must be confirmed with an Airport-only layout dump on the new bounds (see Validation).
- **Footprints.** The full Airport is 210×55 cells (`Assets/Game/Prefabs/Buildings/Building_Airport.prefab:1084-1090`). Its runway length comes from `Runway_Start`/`Runway_End`, which are about 181 m apart (prefab transforms; `Assets/Game/Scripts/Systems/BuildingRunwaySystem.PrefabGeometry.cs:53-77`). The small airport was tested at 150×45, 120×40, 100×30 and 80×25 cells.

   - IB: `Assets/Game/Configs/Skirmish/IndustrialBasin/OperationMap_IndustrialBasin.asset:22`, `:28-31` (playable 740–990 × 420–660; camera 620–1110 × 300–780).

   - `OperationMap_IndustrialBasin` is used by the legacy coded S073 (`Assets/Game/Resources/SkirmishIndustrialBasin.asset`).

## Airport type assumptions in code (small airport question)

- **No small airfield exists.**
  - The only runway building is `Building_Airport.prefab`. `Building_Helipad.prefab` is 16×15.
  - `Assets/Game/Prefabs/Generated/GC04Modules/RunwayApron_DemoAuthored.prefab` is a demo scenery module, not a production building.
- **Single Airport type is hard-wired:**
  - one structure id `building.airport` (`Assets/Game/Scripts/Skirmish/Contracts/SkirmishRosterContracts.cs:274`);
  - a 1:1 prefab key (`:293`, `:316`);
  - `ProducerFor` maps it to `SkirmishProducerKind.Airport` (`:335`; enum `:44-52`);
  - fighter, strike and transport_plane all name `SkirmishProducerKind.Airport` (`Assets/Game/Scripts/Configs/Skirmish/SkirmishRoleCatalogConfig.cs:96-102`; `SkirmishRoleOverlayCatalog.cs:42-47`);
  - eligibility is a single `AirportPresent` (`SkirmishProductionEligibility.cs:70`);
  - the visual key is 1:1 (`Assets/Game/Scripts/Runtime/Skirmish/SkirmishProductionCatalog.cs:127`);
  - the enemy AI builds only `SkirmishStructureIds.Airport` (`SkirmishEnemyStrategySystem.cs:117`, `:480`; `SkirmishEnemyConstructionAdapter.cs:388`);
  - Airport placement requires FullArsenal (`SkirmishNativeProduction.cs:37-38`);
  - the gate-unit model maps producer to structure 1:1 (`Assets/Game/Scripts/Editor/Skirmish/SkirmishS002AriaRunHarness.GateUnits.cs:78`).
- **Roles a small airport would serve:**
  - **Drones need no airport.** The drone is produced by the IntelStation (satellite dish) (`SkirmishRoleCatalogConfig.cs:76-78`; `SkirmishRoleOverlayCatalog.cs:40`). Expanded drones also skip runway homing (`Assets/Game/Scripts/Systems/FixedWingRunwayHomeInitializationSystem.cs:43-47`).
  - The small airport therefore serves **fighter + strike** only.
  - Excluding transport_plane can be done in either of two ways:
    - (a) a per-map army profile that omits `TransportPlane`. This is the smallest change.
    - (b) a new producer kind. This touches the enum, role catalog, eligibility, research, enemy AI and the gate model.
- **Runway mechanics scale with length.**
  - Takeoff uses fractions of the runway: liftoff at 65 %, minimum roll 35 % (`Assets/Game/Scripts/Systems/UnitAirMovementSystem.cs:16-22`).
  - Runway extents are read from any building with a `Runway` child (`BuildingRunwaySystem.PrefabGeometry.cs:28-77`), so a shorter runway is mechanically accepted.
  - Risk: production delivery for runway buildings animates a landing transport plane (`ProductionTransportMode.Plane`, `Assets/Game/Scripts/Systems/BuildingProductionTransportPresentationSystemHelper.cs:84-112`). On a 100 m strip it needs a visual check, or a switch to self-arrival.
- **Proposed small footprint: 120×40 cells**, with the runway about 100 m start to end.
  - It is the largest size that fits the measured west pocket (x 800–844, z 640–772). 130×40 and larger do not fit there.
  - Fallback: 100×30.
  - New assets needed: a prefab variant of the Airport (footprint, runway children, parking spawns, destroyed visual, productions Jet_01 and Jet_02 only) and a new structure id with its mapping.
- **Airport is missing from session definitions.** S026 and S050 sessions do not configure an Airport definition (`Design/Orchestration/notes/airport-probe-2026-11-17.md:76`). Any map that gets an Airport also needs `Building_Airport` (or the small variant) in its configured spawnable list.

## City Crossroads (S026 host; shared world)

1. **Generator.** None is needed. CC is a logical window; clone `OperationMap_CityCrossroads` with extended `bounds` (playable, camera, minimap `projectionOrigin`/`Size` at `:28-31`, `:67-68`). The world minimap covers all 2048×1024, so the shared Campaign assets stay untouched.
2. **Option A: clear in place. Not viable.**
   - No 210×55 or small site is legal inside 900–1300 × 260–875. This agrees with lane9: 3,946 of 3,948 positions rejected by buildings (`Design/Orchestration/daily/lane-probes9-2026-11-17.md:5`).
   - The least-blocked 210×55 position (988–1044 × 260–472, rotated) still overlaps:
     - 69 scenery blocks (about 1,100 m² of city buildings);
     - 121 road/sidewalk blocks;
     - 103 not-level blocks.
   - Even 80×25 needs scenery removed.
   - Clearing would edit the shared desert/dense-city world. That world feeds CH01–CH03 (policy `:33`), Desert Base, S025, IB and CityEdgeAirfield-derived tooling. A Skirmish-only derivative would be a new physical map (policy `:21-23`).
3. **Option B: expand onto existing terrain. Viable.**
   - South of CC lies flat, open, buildable desert (heights 0.01–0.5 m, slope 0, bit 16 everywhere).
   - **Small airports on both sides (recommended):**
     - enemy 120×40 at 1120–1240 × 156–196, 238 m from the enemy base (1100,400);
     - player 120×40 rotated N–S at 804–844 × 644–764, 201 m west of the player base (1020,750);
     - new playable 804–1300 × 156–875 (496×719 vs 400×615, +45 % area);
     - both sites are level and clear of the S026 draft pads;
     - no new terrain or roads.
   - **Big Airport, enemy only:** 980–1192 × 104–160, level, 268 m from the enemy base. Needs south to z ≈ 100 (+156 m).
   - **Big Airport, player:** the nearest level site is 564–776 × 732–788, 350 m away. It needs bounds 564–1300 × 104–875 (+130 % area). Not recommended.
   - A mixed big/small pair is possible but asymmetric.
4. **Effort, risk and benefiting rows.**
   - Effort **M**: a logical clone builder (S), re-measuring the air/combined layouts on the larger window, plus the shared small-airport prefab and code (M, once for all maps).
   - Campaign risk: **none**, provided the clone leaves the existing asset untouched.
   - Benefiting rows (16): S027–S030 (BA), S033–S036 (FC), S039–S042 (BT), S045–S048 (CE).
   - Note: policy `:49` says to pin the source per logical layout and avoid per-S-ID switches. Use one "CC air" layout and bounds for all 16 rows.

   - Example pair: player 948–1160 × 104–160 (237 m from the player base at 1002,363.5) and enemy 1056–1268 × 48–104 (316 m). Combined window 868–1292 × 48–512 (2.3× area).

## Ranking and recommendation

| Rank | Map | Fits | How | Effort | Campaign risk |
|---|---|---|---|---|---|
| 1 | City Crossroads | Small 120×40 for both sides (big possible for enemy only) | Logical clone, +45 % area onto existing flat terrain | M | None |
| 2 | Mountain Pass | Big 210×55 for both sides, only after a source change | B1 shared-world window or B2 Skirmish-only Citywide crop | L | Low if new folder, high if in place |
| 3 | Industrial Basin | Small, player side only | Logical clone, +112 m north | S–M (one side) / L (both) | None |

**Recommendation.**
1. **City Crossroads: give it the small airport on both sides now.** It uses logical bounds only, stays within policy `:14`, and leaves Campaign assets untouched.
2. **Mountain Pass: make it the big-Airport map ("transporter can land") only if the owner explicitly approves.** That means either a Skirmish-only enlarged Citywide derivative (B2, which keeps S049/S050 geometry) or a move to the shared world (B1, which re-measures every MP row). Both routes are new-map or source decisions under policy `:21-23`.
3. **Industrial Basin: keep it helipad-only.** It is the small 250×240 map, and only a one-sided airport fits there. This satisfies "a map without airport but not all".
4. If the owner rejects the MP source change, CC alone still meets the minimum. The IB player-only small airport is then the cheapest second map, but it is asymmetric.

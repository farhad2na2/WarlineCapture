## What the source establishes

The expanded card callback in `SelectionGameplayStartupSystemHelper` captures the UI click, suppresses the world click, toggles the requested group and synchronizes selected entities/HUD. `SkirmishExpandedPresentedOrders` checks an expanded session and a living player group. `SkirmishArmySelectionService` changes group selection/tags and recounts; its selection decision is not a camera result.

`SynchronizeExpandedSelection` calls `ApplySelectionFocus`, whose focus is selection/HUD state. It does not request ground-camera centering. It can clear a prior aircraft-lens context through `ObserveNormalGroundSelection`; a single selected owned aircraft can instead queue the existing aircraft focus path. Adding an unconditional recenter here would affect normal manual selection, deselection/multiple selection and aircraft ownership, without establishing which branch failed in the reported frame.

ARIA `SelectionVisible` is assigned from the selection panel model's `selected.Visible`; it is not a projection test for the selected squad. ARIA's separate `ObserveGroupMap` computes the largest cluster of presented player contacts within its existing radius. It does not identify the actual selected squad. Its full-map target may drag the viewport; its closed-map target opens the map. `AriaSkirmishPlanSystem` already has separate group/map-focus stages before some selection paths and uses card selection as a fallback when a selection rectangle is unsafe. These differences are observable source semantics, not proof that any particular gesture failed or that all card selections should auto-pan.

For accepted map navigation, `HandleFocusRequested` converts the current map projection to a grid-clamped world point. `SelectionUiCameraSystemHelper.MoveCameraGroundCenterTo` updates the pending HUD zoom center, clears competing smooth targets and queues the existing camera request. `RtsCameraSystem.MoveCameraGroundCenterTo` moves X/Z and invokes the ground-boundary clamp. The request layer reads active operation-map camera bounds. This is a legal-map-footprint constraint; it does not guarantee selected actors are visible or unoccluded by HUD. The separate placement helper compensates a supplied viewport center and changes placement/zoom ownership; reusing it blindly for squads would be unjustified. No new clamp, replacement camera API, placement mode or viewport geometry is proposed.

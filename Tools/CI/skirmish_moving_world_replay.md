# Moving world configuration replay

The world runner now has a separate `moving_world` profile that composes production coordinate conversion, occupancy, goal admission, bounded routing, asynchronous result application, infantry path following, acquisition, target validation/synchronization, chase, standard attacks, delayed HP commits, death lifecycle and BA clock/result kernels. Positions, cells, occupancy, health and objective outcomes evolve from these shared kernels. Inputs never provide future positions or HP.

This is a bounded synthetic configuration validator, not a complete game simulation or qualification of the 120 catalog missions. Reports retain `full_battle_simulated: false` and `mission_qualified: false`. It reuses existing map facts; it creates no physical map assets.

## Verified build and tests

Both schedule profiles remain distinct. Supply two receipts from the same passing native validation with unchanged source/settings pins:

```sh
rtk proxy python3 -B Tools/CI/skirmish_world_replay.py build \
  --project . --output /private/tmp/moving-build \
  --schedule-receipt /private/tmp/stationary-order-receipt.json \
  --moving-schedule-receipt /private/tmp/moving-order-receipt.json
rtk proxy python3 -B Tools/CI/skirmish_moving_world_replay_test.py \
  --build /private/tmp/moving-build --output /private/tmp/moving-tests \
  --native-log /absolute/path/to/passing-native.log
```

Run the existing stationary and squad test commands against the same build as well. The standalone runner uses an installed .NET 8 SDK, unchanged compiled kernel source, no downloads and no Unity launch. Every run verifies source, binary, receipt profile and all captured native/package/settings hashes before and after execution.

The moving receipt uses the same exact schema as the stationary receipt, but requires profile `IsolatedMovingCombatScheduleV1`, marker `[MovingWorldSchedulingNativeOrder]`, and fixed pass marker `[SharedMovingLifecycleParity] result=Passed`. The 14-system native sorted subset includes Begin/EndSimulation, occupancy, target validation, acquisition, target sync, engaged movement, pathfinding, grid movement, attack, death, objective projection, BA evaluation and outcome. This is not the full native world order.

`profile.json` contains both independently enabled captured profiles. `profile_sha256` in **either** case type is the SHA256 of this complete build artifact, including both receipts. Changing either receipt requires regenerating cases with the new hash. Missing moving receipt disables moving cases while allowing a separately validated stationary profile and squad queries. Never fabricate a receipt to run a fixture.

## Initial state and controls

Complete examples are generated by `canonical()` and `native_chain()` in `skirmish_moving_world_replay_test.py`. Set that module's `BUILD` to a verified build before serializing the case.

A moving case contains `id`, `kind: "moving_world"`, `profile`, `profile_sha256`, `map`, `units`, `query_orders`, designated `player_base`/`enemy_base`, positive `deadline_seconds`, `frames`, and nonempty `expect`.

Map facts specify dimensions (up to 64×64), exact `GridCoordinateFrame`, provenance, complete walkable/dynamic-blocker/friendly-pass/sidewalk/dirt-road arrays, and per-cell/footprint surface pathability and cardinal/diagonal traversal costs. These are static map facts, not per-frame paths or positions. Synthetic facts must say synthetic; real content must retain its authoritative surface provenance. Only single-cell ordinary infantry and target-only bases without UnitGrid are supported. Base health and positions are initial facts; subsequent base health is derived from attacks.

Each unit wraps the existing exact world `actor` shape plus `movement`. Infantry movement facts contain speed, walk speed, road multiplier, arrival distance, chase-break distance, configured death duration, manual flag, optional initial request and UnitTarget cells, CanAttack flag, optional initial engagement commanded flag, and lifecycle profile `simple_infantry_no_children_no_gpu_no_light_no_carrier`. Base movement must be null. Initial engagement caches come from the referenced target's initial transform using the shared coordinate conversion. Initial recent-attacker state, scan orders, animation-order components, campaign suppression, protected-record actors and unsupported lifecycle profiles are rejected.

All actors retain the explicit default visible/unrestricted/no-fog policy profile. Actor positions and cells must agree with shared WorldToCell at initialization. Moving acquisition then derives each spatial cell from the current transform, with the native UnitGrid fallback. The host rejects more than one living mobile actor in an acquisition cell: native parallel hash-map iterator order cannot be reconstructed from stable entity/insertion order. The stationary profile continues to accept explicit per-cell iterator facts.

`query_orders` supplies every initial identity exactly once for each query: acquisition, spatial, buildings, pathfinding, grid_move, attack, damage, death_begin, death_finalize and engagement. Derived component membership filters these schedules at the corresponding phase. They are explicit synthetic/captured order inputs, not an assertion that native query order is globally stable. Destroyed identities remain in the schedule but are excluded from later queries.

Frames contain elapsed time, delta (0..1), pause/surrender, explicit gameplay-state presence/activity, `path_play_requested`, `path_job_completed`, camera-valid and per-mobile-identity `inside_viewport` facts. Gameplay activity and path play-requested are separate native controls. Worker completion is an external observation, never inferred from machine speed. The host computes route contents itself, stores them pending, and applies only through the shared scheduling gate. Waiting does not apply a path; cancellation drops pending work; a stale result cannot restore a request that acquisition removed. This validates controlled completion timing, not native wall-clock job latency.

## Movement and lifecycle scope

Path scheduling admits one ordinary nonmanual 1×1 request per batch within the shared 32-cell segment limit. The shared desired-goal identity branch must accept the goal using shared placement and surface facts. Multiple requests, nearest-free reassignment fallback, manual/long-distance scheduling and segmented results are rejected. This avoids copying reservation, hierarchical segmentation or budget policies into a second implementation. Normal routing retries, search budgets and alternate-goal order still execute the production routing kernel. A failed ordinary result follows the production Abandon intent. Manual retry restoration requires `UnitManualMoveRetrySystem`, which is outside this profile; the runner does not claim to simulate it.

Native occupancy refresh happens only at the captured occupancy phase. Pathfinding may precede the first refresh; its initial route therefore reads the initially empty occupancy state rather than a fabricated pre-pass. Overlap counts update with the shared occupancy kernel. Movement uses the captured stale/current occupancy bitset together with a separate immutable snapshot of live UnitGrid footprints, including corpses until their actual removal. The path-follow kernel preserves the native first-waypoint-only admission behavior; it does not add extra obstacle checks on subsequent same-frame waypoint advances.

Acquisition publishes at EndSimulation and removes follow/range/request state there. Newly acquired units do not chase or fire in the acquisition frame. Target validation removes invalid engagement immediately and may restore a request from UnitTarget; synchronization refreshes cached target positions before chase, with its own deferred removal boundary. Grid movement and completion use shared intents; ordinary completion clears UnitTarget at EndSimulation and resets speed/stall immediately.

Attacks plan against one pre-damage snapshot and use shared predicted-health sequencing and ordered aggregate commits. Native local attack ECB effects complete before EndSimulation acquisition removals. Nonlethal damage that could invoke unshared counter-engagement or flee is rejected, including unarmed actors even if they retain an engagement.

Death strips exactly the supported active components, begins configured ordinary infantry animation, ticks it in the same native update, freezes pose on first expiry, and removes only on a later valid-camera/offscreen decision. No respawn is invented. Corpses remain actors and keep the native unusual acquisition eligibility; CanAttack and preserved combat flags govern acquisition. Pending acquisition may re-add engagement after death stripping. A destruction that conflicts with an outstanding EndSimulation command is rejected rather than guessed. No GPU clips, descendants, transport, lights, visibility consumers, audio or VFX side effects are synthesized.

The captured projection/BA/outcome phases derive base health and freeze one result. Projection's no-surrender terminal precedence and any one-frame damage observation delay are preserved. The runner stops at the first frozen result and reports consumed/remaining frames.

## Evidence

The suite exercises a generated route, actual chase and kill, corpse continuation, target invalidation and resumed routing, then damage to the enemy base and a derived BA victory. It repeats two independent configurations and 120 distinct synthetic configurations varying movement speed, guard position/HP and base HP, comparing complete reports and recording timing without claiming catalog wins.

A separate comparison consumes the hash-verified `[EngagedMovementNativeTrace]` from the passing native suite. It checks every native row's actor/target positions, grid cells, HP, engagement identity and cached target position, path-request membership and corpse frozen state. That actual native subset intentionally has no pathfinding or objective systems; its parity evidence is reported separately from synthetic route-to-result checks. Native UI, normal input, ARIA, device play and campaign content acceptance remain separate gates.

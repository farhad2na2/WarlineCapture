# Protected expanded normal-input authority gap

This source-only proposal audits published `f2a1b825c12e9c5597789fdaf4da679ebb7761af`. It issues no authority and starts no native run. Windows Runtime owns the private QA selection/dispatch/save/resume implementation; this patch does not duplicate its UI work. All 720 canonical tuples remain, including the 18 protected tuples listed in `proposal.disabled.json`.

The real expanded path is partly present: `ProductionCanary.cs:188–206` loads the persisted counterpart, opens a private Editor-memory catalog overlay and calls the existing normal `RunEditorJourney`. `SkirmishLaunchProjection.cs:26–46,103–107` requires an explicit `ExpandedDefinition` selection and queues the actual compiled definition. The missing contract is a separately reviewed, versioned **normal dispatch authority plus actual native tuple-fit authority**. The old schema3 authority explicitly proves only development materialization and edit-mode public-method readbacks; its `actual_normal_input_play=false` and `baseline_credit=0` must remain unchanged. Ordinary schema2 legacy results are also zero expanded baseline credit and have a distinct `legacy-native-runs.csv` with `Normal`/`CodedPreset` fields. Neither is a replacement for a genuinely expanded mission.

The minimal code proposal changes only inspector evidence classification. Before this patch, an otherwise consistent constructed schema3 protected counterpart batch produces `wins=1` for its Victory, despite its development authority. The exact same raw artifacts now retain Victory/Defeat/Draw and `actual_native_wins=[1,0,0]`, but expose `wins=0`, `evidence_scope=DevelopmentCounterpartZeroBaselineCredit`, and `sampling_coverage_credit=0`. Existing ordinary expanded normal counts remain unchanged and unqualified. A protected catalog cannot evade classification by changing its job to schema1, and an unknown future schema fails closed. This is a counterexample using constructed artifacts, not a claim that any existing real native result was accepted or a replacement authority validator. The prior inspector already required full owned artifacts and kept qualification/queue success false.

The runtime proposal must cover three separate boundaries. First, selection needs an explicit definition/version/launch-kind identity and independently pinned dispatch/fit authorities; a historical scenario index or mutable IsPlayable flag is insufficient. Second, source load must retain that authority: `SkirmishGenericMissionSource.TryResolve` currently re-queries the current battle catalog at lines79–84, even with a session-owned launch definition. Third, save/resume must revalidate the same identity: `SupportsGenericSave` and `TryRead` use current main battle/authored catalogs. A queue-only token or a scope disposed after selection will not carry the private definition safely through load and resume. The launch definition record already captures source/layout/setup identity and fails closed on partially lost expanded ownership; preserve these checks when introducing private QA resolution.

Native counterpart `Compile` currently fixes Regular/Standard and compiles each packet seed; the overlay's early three-size check uses seed1. Neither replaces the Runtime owner's independently measured tuple-fit authority. Reuse existing Campaign physical geometry and preserve shipped preset resources, main catalog bindings, existing saves, IDs, seeds, locales, and failures. No new geometry, difficulty/size relabel, slot omission, claim retry or development-to-normal transfer is proposed.

After Windows freezes its independently reviewed authority interfaces, a separate small queue/native-request/collector integration must recognize the new authority explicitly, bind it to source/build and actual setup/content identity, and carry it through normal contact/ARIA/Playing/Finished/result/return, profile restoration and owned cleanup. This patch accepts no new normal counterpart schema. Camera boundary evidence remains pending. Visual review, normal play, device acceptance and queue qualification remain separate gates.

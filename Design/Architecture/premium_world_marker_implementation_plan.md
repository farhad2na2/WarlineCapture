# Premium World Marker Implementation Plan

Date: 2026-06-13
Status: Complete
Owner: Gameplay

## Goal

Create one unified premium holographic marker family for all live world markers:

- building selection;
- unit and vehicle selection;
- unit move target markers;
- unit attack target and attack ground markers;
- ground missile launcher target locks;
- entity attack target locks;
- attack and board target previews.

The work is a visual/rendering upgrade. It must not change selection rules, command validation, attack behavior, missile targeting behavior, marker lifetimes, or command result routing unless a later task explicitly requests that behavior change.

## Architecture Contract

- Do not add a marker manager, controller, facade, singleton, service locator, or broad orchestration shell.
- Building selection marker projection remains owned by `BuildingSelectionMarkerPresentationSystemHelper`.
- Unit and vehicle selected marker instances remain owned by `UnitSelectionMarkerSystem`.
- Move markers, attack markers, entity target-lock markers, attack previews, board previews, marker GameObject lifetime, marker material property blocks, marker show/hide timers, and marker world positioning remain owned by `SelectionOrderMarkerPresentationSystemHelper`.
- `RtsSelectionCommandResultFlushCompositionSystemHelper` may route accepted command results to `SelectionOrderMarkerPresentationSystemHelper`, but it must not own marker visual policy.
- UI views must not own world marker state or mutate gameplay marker objects directly.
- Building, unit, and vehicle gameplay prefabs must not regain persistent marker children where the architecture contract forbids them.
- Runtime source must stay inside the existing bounded assemblies. Do not add runtime code that falls back into default `Assembly-CSharp`.

## Visual Language

Use one shared holographic tactical family, with different shape, color, and intensity per marker purpose:

- Selection: calm cyan/green, low pulse, thin brackets/rings, low visual noise.
- Move target: blue/cyan destination ping, short-lived ripple or directional brackets.
- Attack ground/world point: red/orange strike reticle, sharper pulse, short-lived.
- Entity and missile target lock: red/orange footprint lock, strongest scan/pulse, persistent for the current target-confirm duration.
- Board/valid target preview: teal/cyan, low intensity.
- Attack preview: low-intensity red, readable at map scale without competing with confirmed target locks.
